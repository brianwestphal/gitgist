| FR-24 | Self-contained output — no cross-reference or dedupe sections: the generated notes/commit message always fully describe each software change and never emit meta content deferring to another document ("Carried over from … — dedupe against the draft above", "already in the changelog", "see also"), nor tell the reader to reconcile two documents. This holds even when an existing changelog `Unreleased` entry is part of the input, which is exactly when models are prone to it: such an entry is treated as *evidence of what changed*, to be described in full. De-duplicating against a `CHANGELOG.md` is an external tool's responsibility, out of scope for gitgist | **Shipped** | Shared `NO_CROSS_REFERENCE_RULES` rule block (`prompt.ts`) interpolated verbatim into `SYSTEM_PROMPT`, `TEMPLATE_SYSTEM_PROMPT`, and `COMMIT_SYSTEM_PROMPT`, so the rule cannot drift between output formats. |

| FR-25 | Diff-grounded generation (**on by default**): every AI run over a commit range also reads the range's **actual code diff** (`readRangeDiff`) and feeds it to the model as the authoritative record of what changed. Commit subjects/bodies and changelog or documentation files in the range are secondary evidence — the model is told the diff wins on conflict, must report user-facing changes visible only in the diff, and must drop claims the diff does not support. `--no-diff` / `diff: false` opts out (commit messages only); the deterministic `--no-ai` path never reads a diff | **Shipped** | `git.ts:readRangeDiff` + `prompt.ts:rangeDiffToMaterial`/`DIFF_IS_SOURCE_OF_TRUTH_RULES` (embedded in all three system prompts); orchestrated in `releaseNotes.ts`. Spec in [7-diff-grounding.md](7-diff-grounding.md). |
| FR-26 | Bounded, noise-filtered diff material, applied **uniformly to both diff paths** (the commit-range patch and the working-tree diffs): bodies are capped at one shared char budget (default 24000, `--max-diff-chars`; allocated per file — FR-29) and generated/lockfile/vendored paths are excluded from them, while the **complete changed-file lists and the range stat are always kept**. The working-tree budget is shared across only the sections that actually have content, so a lone `--staged` run gets all of it. Anything held back — a truncated patch, or files whose diff was dropped as noise — is stated in the prompt so the model knows the limit of what it may claim | **Shipped** | `git.ts` (`NOISE_PATHSPECS`, `capText`, `shareBudget`, `MAX_STAT_CHARS`, `DEFAULT_MAX_DIFF_CHARS`); reported by `prompt.ts:rangeDiffToMaterial` / `workingChangesToMaterial` via `RangeDiff`/`WorkingChanges` `excluded`+`truncated`. Spec in [7-diff-grounding.md](7-diff-grounding.md). |
| FR-27 | Configurable diff exclusions: `--exclude <pathspec>` (repeatable) adds patterns on top of the built-in `DEFAULT_EXCLUDES`, and `--no-default-excludes` drops the built-in list entirely — for repos where a default is wrong (a published `dist/`, a Go `vendor/` that *is* the change). Applies to both diff paths. FR-26's visibility invariant is preserved: an excluded file's **patch body** is held back, but it stays in the changed-file list and stat and is named in the prompt | **Shipped** | `git.ts` (`DEFAULT_EXCLUDES`, `buildExcludePathspecs`, `withPathspecs`); `DiffExcludeOptions` threaded through `readRangeDiff`/`readWorkingChanges`/`generateReleaseNotes`. Spec in [8-exclusions.md](8-exclusions.md). |
| FR-28 | Provider-advertised diff budget: `AIProvider.diffBudgetChars` sizes the diff material to the backend that will read it, instead of one shared number for context windows spanning three orders of magnitude (`apple` ~4k tokens → `anthropic-api` 1M). Precedence: `--max-diff-chars` → the resolved provider's budget → the shared default. The primary provider is resolved **before** the diff is read (one availability probe, reused for generation); a resolution failure is **deferred** and rethrown at generation time so the FR-23 fallback still applies (T-2) | **Shipped** | `providers/types.ts` (`AIProvider.diffBudgetChars`); per-provider values in `cli.ts`/`anthropicApi.ts`/`local.ts`/`apple.ts`; precedence + early resolution in `releaseNotes.ts`. Spec in [9-provider-budgets.md](9-provider-budgets.md). |
| FR-29 | Per-file diff budget allocation: the patch budget is shared across **every changed file** (max-min fair / water-filling — smallest first, each offered an equal share of what remains, unused allowance flowing back to larger files) rather than keeping the first N characters of the concatenation. `git diff` emits files in path order, so the old positional cut spent the budget alphabetically and gave late-sorting files **nothing**. Files shortened rather than dropped are reported in `trimmedFiles` and named in the prompt. Ecosystem-neutral: no path is ranked above another | **Shipped** | `git.ts` (`capPatch`, `splitPatchByFile`, `sliceToLine`), applied to both the range patch and each working-tree section; surfaced by `prompt.ts:rangeDiffToMaterial`/`workingChangesToMaterial` via `RangeDiff`/`WorkingChanges` `trimmedFiles`. Spec in [7-diff-grounding.md](7-diff-grounding.md). |
| FR-30 | Commit attribution: each commit in the prompt carries its short hash and the files it touched (`readCommitFiles`, one `git log --name-only`), so the model can tie a change to the commit that made it, group changes touching the same files, and read landing order. Chosen over per-commit patches, which cost 1.2–1.7× the net diff to repeat hunks the model already has and *reduce* effective coverage (GG-55). Sized to ~15% of the diff budget and dropped entirely when it won't fit; honours FR-27 exclusions; the model may only cite a hash it can see. `--no-attribution` opts out | **Shipped** | `git.ts:readCommitFiles`; `prompt.ts` (`commitsToMaterial`, `CommitAttribution`, `attributionFilesPerCommit`, `ATTRIBUTION_RULES` in all three prompts); `releaseNotes.ts`. Spec in [10-attribution.md](10-attribution.md). |
| FR-31 | Visible commit provenance: `--link-commits` makes every bullet end with the commit it came from — a Markdown link when a commit URL is available, else a bare hash. The URL comes from `--commit-url <template>` (must contain `{hash}`) or is derived from the `origin` remote for hosts whose commit-page shape is known (GitHub/GitLab `/commit/`, Bitbucket `/commits/`); an unrecognized host yields bare hashes rather than a guessed URL. A bullet spanning several commits cites **all** of them. Requires FR-30 attribution; ignored for `--format commit` like `--title` | **Shipped** | `git.ts` (`commitUrlFromRemote`, `detectCommitUrl`); `prompt.ts:buildCommitLinkRules` appended to the system prompt in `releaseNotes.ts`. ## State transitions

Line/branch coverage is structurally blind to a missing **state transition**: a
multi-step sequence can be wrong even when every individual line runs under an
isolated, single-operation test. These are the transitions across the project's
stateful paths (the provider fall-through chain and the AI-generation state
machine in `releaseNotes.ts`); each must be exercised by a test that *walks the
sequence*, not just each state from a clean start. They are tracked as first-class
requirements (`T-N`) and enforced by `npm run check:features`.

| ID | Transition | Status | Notes |
| --- | --- | --- | --- |
| T-1 | Provider auto fall-through | **Shipped** | `resolveProvider('auto')` skips an *unavailable* provider and returns the next available one in `AUTO_ORDER`; errors only when **all** are unavailable. Walk: unavailable → next → none. |
| T-2 | Primary error → fallback → deterministic | **Shipped** | `generateViaAI`: primary provider throws → configured fallback is tried → (fallback recovers ⇒ its notes) or (fallback also throws ⇒ warn + keep primary / deterministic changelog); no fallback ⇒ the error propagates. |
| T-3 | Suspect empty-notes → deterministic | **Shipped** | Notes path: AI returns the empty-notes sentinel **with** commits in range ⇒ suspect ⇒ (fallback, then) deterministic changelog; the **same** sentinel with a working-tree-only run (no commits) is **trusted** and returned as-is. |
| T-4 | Fallback config inheritance | **Shipped** | `runFallback`: the provider-specific model/endpoint are inherited from the primary only when the fallback is the **same** provider; a **different** fallback provider uses its own default unless an explicit `--fallback-model`/`--fallback-endpoint` is given. |
| T-5 | Diff read fails → degrade to prose | **Shipped** | Read commits → `readRangeDiff` throws (unresolvable rev, shallow clone) → **warn, do not fail**: generation continues from the commit messages alone and still returns notes. Walk: commits read → diff error → warning → AI call whose prompt has no diff section → notes. |
